# 세정 LMS — 제품 요구사항 정의서 (PRD)

버전 0.1 · 작성 2026-08-21 · 벤치마크: 대치온(daechion.com) → 상세 분석은 [daechion-analysis.md](./daechion-analysis.md)

---

## 0. 한 줄 정의

**세정 LMS는 세정학원 강사별 브랜드 공간(`/s/{slug}`)을 발급하고, 그 안에서 성적·클리닉·알림을 하나의 자동 연쇄로 묶는 학원 운영 시스템이다.**

대치온과 같은 문제를 풀되, **팔지 않는다.** 대치온은 강사에게 SaaS를 판매하는 멀티테넌트 제품이고, 세정 LMS는 한 학원 안에서 쓰는 내부 제품이다. 이 한 줄이 아래 모든 스코프 결정의 기준이다.

---

## 1. 배경 — 무엇이 이미 검증됐나

대치온은 200명 이상의 대치동 강사가 월 99,000~299,000원을 내고 쓰는 제품이다. 즉 아래 페인포인트는 **가설이 아니라 시장이 지불로 증명한 사실**이다:

> 성적은 **엑셀**로, 질문은 **네이버카페**로, 연락은 **문자메시지**로, 영상은 **유튜브**로.

세정도 동일한 상태다. 우리가 새로 검증할 것은 "이게 문제인가"가 아니라 **"우리 규모에서 어디까지 만드는 게 이익인가"** 뿐이다.

### 대치온이 실제로 돈을 받는 지점 (모방 우선순위의 근거)

| 기능 | 대체 난이도 | 세정 판단 |
|---|---|---|
| OMR 자동생성 + 스캔 인식 + 학생 자동 매칭 | **최상** (OCR/CV 파이프라인) | Phase 3 이후, 또는 외주/외부 API |
| 성적 미달 → 재시험 → 미완료 할 일 → 클리닉 재촉 **자동 연쇄** | 중 (순수 도메인 로직) | **Phase 1 핵심. 여기가 진짜 제품이다** |
| 알림톡 40종 + 데이터 삽입 변수 | 중 (템플릿 심사가 리드타임) | Phase 2, 템플릿 심사 즉시 착수 |
| 조교 출퇴근·급여 정산 | 하 | Phase 2 |
| 영상 워터마크/유출 모니터링 | 상 (인코딩 비용) | Phase 3, 초기엔 외부 링크 허용 |

## 2. 목표 / 비목표

### 목표 (G)
- **G1** 강사 1명당 성적 처리·공지·클리닉 배정에 드는 주간 시간을 **50% 이상 절감**
- **G2** 학생·학부모의 "성적 나왔나요 / 등원했나요" 개별 문의를 **알림 자동화로 흡수**
- **G3** 강사가 교체돼도 학생 이력(성적·상담·클리닉)이 **학원에 남는다** — 스키마상 `students.branch_id` 소속인 이유
- **G4** 강사별 브랜딩(아이콘·테마색)을 유지해 "OOO쌤 수업"이라는 학생 인식을 깨지 않는다

### 비목표 (NG) — 대치온에 있지만 우리는 안 만든다
- **NG1** 외부 판매 / 요금제 / 결제 / 슈퍼관리자 SaaS 콘솔 — 내부 제품이므로 전부 불필요
- **NG2** 가입 신청 위저드(`/submit`), 토스페이먼츠 연동
- **NG3** 서브도메인 테넌트 발급 — 경로 기반 `/s/{slug}`로 충분 (인증서·DNS·배포 복잡도 제거)
- **NG4** 자체 영상 인코딩/플레이어 — Phase 3까지 외부 링크(YouTube 미등록/Vimeo) 허용
- **NG5** 단어장, 노션형 협업 에디터, 종이 성적표 디자이너 — 학원 규모 대비 ROI 낮음

### 성공지표 (KPI)
| 지표 | 기준선 | 목표 |
|---|---|---|
| 차시 1건 성적 입력~공개 소요 시간 | 엑셀 기준 측정 필요 | 15분 이내 |
| 성적 공개 후 개별 문의 건수 | 측정 필요 | 80% 감소 |
| 클리닉 미등원율 | 측정 필요 | 리마인더 도입 후 절반 |
| 주간 활성 강사(WAT) / 전체 강사 | — | 80% |

## 3. 사용자 & 역할

기존 스키마의 `app_role` enum과 1:1로 맞춘다.

| 역할 | 누구 | 핵심 니즈 | 주 사용 기기 |
|---|---|---|---|
| `admin` | 세정 운영/실장 | 전 공간 통계, 계정·근태·급여, 정책 설정 | 데스크톱 |
| `teacher` | 담당 강사 | 강의·차시 운영, 성적 공개, 학생 상태 파악 | 데스크톱 + 모바일 |
| `assistant` | 조교 | 채점, 클리닉 등·하원 처리, 질의응답 답변 | **모바일 우선** |
| `student` | 학생 | 오늘 할 일, 성적 확인, 클리닉 예약, 자료·영상 | **모바일 전용** |
| `parent` | 학부모 | 성적·출결 확인, 피드백 열람 | **모바일 전용, 로그인 최소화** |

> **설계 원칙**: 조교의 클리닉 처리와 학부모 열람은 **모바일에서 로그인 없이 3초 안에** 끝나야 한다. 이게 안 되면 알림톡을 아무리 보내도 카톡으로 되돌아온다.

## 4. 제품 구조 — 역할이 아니라 "앱 4종"으로 나눈다

대치온 분석에서 얻은 가장 중요한 구조적 교훈. 역할별로 화면을 나누면 권한 분기가 화면마다 번지지만, **앱 단위로 나누면 앱 경계 = 인증 경계**가 된다.

```
/                          런처 — 내 쌤 아이콘 목록 (학생/학부모 진입점)
/s/{slug}/admin/*          [CRM]    관리자·강사·조교 — 데스크톱 밀도 높은 UI
/s/{slug}/student/*        [SP]     학생 포털 — 모바일 탭바 UI
/s/{slug}/parent/*         [SP-P]   학부모 포털 — 읽기 중심
/s/{slug}/board/*          [BOARD]  공개 게시판 — 비로그인 열람 가능(설정)
/l/{token}                 [LINK]   ★ 매직링크 — 로그인 없이 단일 동작 수행
```

### 4-1. `[LINK]` 매직링크 — 반드시 Phase 1에 포함

알림톡/문자에서 온 링크를 눌렀을 때 **로그인 화면이 뜨면 그 기능은 죽는다.** 대치온이 10종의 `/link/*` 라우트를 별도로 둔 이유다.

| 라우트 | 동작 | 수신자 |
|---|---|---|
| `/l/{t}` → `clinic-arrived` | 등원 처리 1탭 | 조교 |
| `/l/{t}` → `clinic-departed` | 하원 처리 + 피드백 작성 | 조교 |
| `/l/{t}` → `report` | 차시 성적표 열람 | 학생·학부모 |
| `/l/{t}` → `todo` | 미완료 할 일 확인 | 학생 |
| `/l/{t}` → `qna` | 질문 답변 확인 | 학생 |
| `/l/{t}` → `survey` | 설문/신청 응답 | 학생·학부모 |
| `/l/{t}` → `temp-login` | 임시 로그인 | 전체 |

**토큰 요구사항**: 1회성 아님(재열람 허용) · TTL 설정 가능(기본 14일) · 대상 사용자·액션 바인딩 · 쓰기 액션(등원/하원)은 **1회 소비 + 멱등** · 열람 로그 기록.

자녀 선택 → 성적 요약 · 출결 · 클리닉 이력 · 강사 피드백 · 공지. **쓰기 동작 없음**(설문 응답 제외).

## 6. 기능 요구사항

우선순위: **P0** = MVP 필수 / **P1** = 정식 오픈 / **P2** = 이후

### F-1. 강의 · 차시 (P0)
- F-1.1 (P0) 강의 CRUD — 이름·과목·요일/시간 반복·색상·담당 강사/조교
- F-1.2 (P0) 차시(session) 자동 넘버링, 카드 뷰, 종강 처리
- F-1.3 (P0) 수강생 배정 — 직전 차시 불러오기 / 엑셀 붙여넣기 / 일괄 추가
- F-1.4 (P1) 반 이동 — 성적·자료 권한 함께 이관
- F-1.5 (P1) 지난 시즌 강의 복사 (텍스트 치환 + 날짜 일괄 이동)
- F-1.6 (P0) 출결 — 현장/영상/지각/조퇴/결석/부재/미정, 일괄 변경, 출결 메모

### F-2. 성적 (P0) — **제품의 심장**
- F-2.1 (P0) 시험/과제 생성 — 문항 수, 배점, **소수점 배점**, **복수정답**, 예외답안
- F-2.2 (P0) 점수 단위: 점 / % / 이행(완료100·일부50·미이행0) / ABCDF. `-1` = 미제출
- F-2.3 (P0) 성적 입력 — 수동 그리드 + 엑셀 일괄 업로드(양식 제공)
- F-2.4 (P0) 통계 자동 산출 — 평균·표준편차·등수·등급(5/9등급)·상위10% 평균·최고점·**문항별 정답률**·선지별 선택률
- F-2.5 (P0) 성적 공개 상태 `OPEN/CLOSED`, 공개 후 답안 수정 시 **학생 성적표 실시간 반영**
- F-2.6 (P0) 학생 성적표 — 차시별 + **누적 성적표**(추이 그래프)
- F-2.7 (P1) 현장/온라인 응시자 **분리 또는 통합** 통계 기준 선택
- F-2.8 (P1) 재시험 — 여러 차수 기록, 상태 enum: 미입력/채점대기/통과/미통과/협의통과/구두통과/포기
- F-2.9 (P2) 문항 유형 등록 + 유형별 석차·평균·취약유형 분석
- F-2.10 (P2) 오답노트 자동 제작 (틀린문제+해설+동형문제, 중철 제본 PDF)
- F-2.11 (P2) OMR 답안지 자동 생성 · 스캔 인식 · 학생 자동 매칭
- F-2.12 (P2) 다중 조교 동시 채점 실시간 동기화 (Supabase Realtime)

### F-3. 자동 연쇄 (P0) — **대치온 대비 우리가 대등해질 수 있는 유일한 지점**
가장 베끼기 쉬우면서 체감 가치가 가장 큰 부분. 7장의 설정으로 정책이 바뀌어야 한다.

```
시험 채점 완료
  └→ 커트라인 미달 판정          (설정: 기본 커트라인)
      └→ 재시험 자동 생성         (설정: 1차 미달 시 2차 생성 여부)
          └→ 학생 [할 일]에 '미완료' 표기
              ├→ 온라인 제출 필요 알림
              └→ 클리닉 예약 재촉 알림
                  └→ 미예약자 = [관리 대상자] 목록에 자동 편입
                      └→ 예약 완료 → 리마인더 → 등원 알림
                          └→ 미등원 → 재촉 알림
                              └→ 하원 → 조교 피드백 작성 → 학부모 발송
```
- F-3.1 (P0) 커트라인 판정 → 할 일 생성
- F-3.2 (P0) 할 일 목록 (학생 SP `/` + CRM `/clinic/todo`)
- F-3.3 (P1) 관리 대상자 자동 편입 (미예약 / 미제출)
- F-3.4 (P1) 재시험 자동 생성 정책 엔진

### F-4. 클리닉 · 상담 (P0)
- F-4.1 (P0) 세션 생성 — 일시·장소·정원, **강의별 여석 쿼터**, 예약 오픈/종료 시각
- F-4.2 (P0) 학생 직접 예약 + 조교 대리 예약
- F-4.3 (P0) 등원 / 재촉 / 하원 처리 (개별 + 일괄), 매직링크 1탭 처리
- F-4.4 (P0) 하원 시 조교 피드백 작성 → 학부모 발송
- F-4.5 (P1) 주간 최대 예약 횟수 제한, 학생 취소 가능 여부
- F-4.6 (P1) 담당 조교 자동 추천 (오늘 담당 + 과거 담당 이력)
- F-4.7 (P1) 상담 — 대면/유선, 상담일지, 리마인더

### F-5. 알림 (P1) — **채널 결정이 선행 과제**
- F-5.1 (P1) 발송 대상 선택: 학부모+학생 / 학부모만 / 학생만 (번호 없으면 대체)
- F-5.2 (P1) **데이터 삽입 변수**: `{강의명} {차시} {시험명} {점수} {평균} {등수} {등급} {통과여부} {피드백} {조교코멘트} {링크}`
- F-5.3 (P1) 매직링크 자동 첨부
- F-5.4 (P1) 예약 발송, 발송 전 최종 확인, 발송기록 조회
- F-5.5 (P1) 템플릿 카테고리: 클리닉(15) / 상담(5) / 성적(6) / 할일(3) / Q&A(4) / 영상(2) / 운영(6) / 계정(4)

## 7. 테넌트 설정 (Feature Flags) — 정책은 코드가 아니라 데이터

대치온의 가장 영리한 장치. 강사마다 "우리는 이렇게 하는데요"가 반드시 나오는데, 그걸 매번 코드로 받으면 제품이 무너진다. **`space_settings` 테이블 하나(JSONB)로 흡수한다.**

| 그룹 | 설정 |
|---|---|
| 출결 | '라이브' 유형 추가, '응시' 유형 추가, 색상 팔레트 |
| 차시 | 미래 차시 숨김, 직전 차시 불러오기(퇴원생 포함), 수강생 수 산정(보강 제외) |
| 시험 기본값 | 기본 제출 방식(현장/온라인), 기본 공개 여부, **기본 커트라인**, 주관식 자동채점 |
| 재시험 | 1차 미달 시(2차 생성/안 함), 2차 미달 시(3차/미통과/협의통과/무처리), 겉면 점수를 마지막 재응시 점수로 |
| 성적표 | 내용 세로 나열, 문제·정답 파일 열람 허용, 등급 표시 |
| 할 일 | 학생 개별 할 일 기능, 숨김 시험/과제 제외 |
| 자료 권한 | 부여 정책 3종, 학부모 권한, 워터마크 기본 단계 |
| 영상 권한 | 부여 정책 2종, 학부모 권한, 워터마크 |
| 클리닉 | **주간 최대 예약 횟수**(1~3/무제한), 학생 취소 가능, 하원 알림에 조교 이름 표시 |
| 상담 | 최대 상담 횟수(주 1~2 / 월 1~4 / 무제한) |
| 질의응답 | 기본 비공개, 답변 알림 대상, placeholder 문구 |
| 게시판 | 수강후기 마스킹(첫 글자/첫 자음), 정렬, 공개 게시판 비활성화 |
| 학생 화면 | **섹션 드래그 순서 + 표시/숨김**, 메뉴 이름 변경 |
| 급여 | 휴게시간 자동 차감, 조교 본인 출퇴근 수정 허용 |

> **구현 지침**: 설정은 `getSettings(spaceId)` 한 곳에서만 읽고, 기본값은 코드 상수로 둔다. 화면마다 `if (setting)` 이 흩어지면 대치온의 8탭짜리 설정 화면도 감당 못 한다.

## 11. 대치온과 의도적으로 다르게 가는 것

| 항목 | 대치온 | 세정 LMS | 이유 |
|---|---|---|---|
| 테넌트 경계 | 서브도메인 (강사 = 고객) | 경로 `/s/{slug}` (강사 = 공간) | 내부 제품, DNS/인증서 복잡도 제거 |
| 학생 소유 | 테넌트(강사) 종속 | **학원(branch) 소속** | 강사 교체 시 이력 유지 |
| 프론트 | Vite + React SPA + MUI | **Next.js App Router + TDS** | SEO 불필요하나 RSC로 초기 로딩·권한 서버 판정 이득 |
| 과금 | 활성 학생 수 3구간 | **없음** | 내부 제품 |
| 알림 | 알림톡 전면 | **웹푸시 우선 → 알림톡 추가** | 템플릿 심사 리드타임 회피 |
| 영상 | 자체 인코딩·플레이어 | 외부 링크 → 이후 자체 | 초기 인프라 원가 회피 |
| 여러 강사 동시 수강 | 사이트가 달라 각각 로그인 | **런처 하나에 쌤 아이콘 N개** | 학생 UX 우위 — 우리가 이기는 지점 |

**마지막 행이 세정 LMS의 유일한 구조적 우위다.** 대치온 구조에서는 한 학생이 수학·영어 두 강사를 들으면 사이트 두 개에 각각 로그인해야 한다. 세정은 런처 하나로 끝난다. 제품 서사를 여기에 건다.
